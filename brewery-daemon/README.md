# brewery-daemon

The Kotlin/JVM sidecar of the Brewery IDE. It speaks JSON-RPC over stdio (LSP-style
`Content-Length` framing) and gives the editor a model of the opened project: build
tool, modules and tasks.

## Build

```
./gradlew test shadowJar
```

The fat jar lands in `build/libs/brewery-daemon-all.jar`. Run it with
`java -jar build/libs/brewery-daemon-all.jar`; it needs JDK 21.

## Protocol

The wire protocol is described in the Brewery daemon protocol spec in the repository's
design documents. Example payloads live in `protocol/fixtures/`.

## Databases (daemon)

The daemon owns database access for the editor's Database tool window.

- `db/drivers`, `db/drivers/addJar`: bundled drivers `postgresql`, `mysql` and `mariadb`
  (both served by MariaDB Connector/J), `sqlite`, plus user JDBC drivers. Each user
  driver is loaded from its jars in its own class loader.
- `db/connections/list|save|delete|test`: connections are stored per project in
  `.brewery/db.json`. The file never contains passwords.
- `db/introspect { connectionId, path }`: lazy schema tree (catalogs or schemas, tables,
  views, sequences, then `columns`, `indexes` and `foreignKeys` folders).
- `db/schema { connectionId, refresh? }`: flat snapshot for SQL completion (schemas, each
  with tables and views, each with columns and types; at most 5000 tables, then
  `truncated: true`). SQLite has one schema named `""`, MariaDB/MySQL catalogs are
  schemas, system schemas are left out. The snapshot is cached per connection until
  `refresh: true`, a DDL statement (`CREATE`, `ALTER`, `DROP`, `RENAME`, `TRUNCATE`)
  through `db/execute`, or save/delete of the connection. A cache hit does not touch the
  database, and concurrent misses share one build. A build uses metadata calls only and
  never ends streaming cursors: on MariaDB/MySQL (whose driver drains a pending result
  when another command runs) it uses a short-lived separate connection on its own thread;
  elsewhere it runs on the connection's session. When there are more than 5000 tables the
  limit is shared fairly between schemas. Changes made outside the editor, or by
  statements such as `SELECT ... INTO`, `CALL` or `ATTACH`, show up after `refresh: true`.
- `db/execute`, `db/fetch`, `db/cancel`, `db/close`: SQL runs on one thread per
  connection. Query results stay on the server as cursors and are pulled in pages
  (fetch size 500); `fetch` only moves forward. Values arrive as strings: binary as
  `0x` hex (first 64 bytes), long text cut at 10 000 characters.
- Errors: -32010 connection failed, -32011 authentication failed (SQLState `28*`),
  -32012 query failed (driver message and SQLState), -32013 unknown connection or cursor.

Passwords go to the operating system's secret store through java-keyring (Windows
Credential Manager, Secret Service on Linux, macOS Keychain) under service `brewery-db`
and account `<project root>#<connection id>`. When no secret store is available the
password is not saved and the connection reports a warning.

Driver licences: PostgreSQL JDBC (BSD-2-Clause), MariaDB Connector/J (LGPL-2.1-or-later,
shipped unmodified), SQLite JDBC (Apache 2.0), java-keyring (BSD-3-Clause) with JNA
(Apache 2.0 / LGPL-2.1-or-later). MySQL Connector/J is not bundled because of its GPL
licence. The full list is generated by `./gradlew thirdPartyNotices`.

Tests for PostgreSQL and MariaDB use Testcontainers and are skipped when Docker is not
available.
