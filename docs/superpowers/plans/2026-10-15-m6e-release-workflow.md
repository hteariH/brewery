# Brewery M6e — Release Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Pushing a `v*` tag builds Brewery for the stable channel, packages it for every platform with the CI-proven scripts, checks the packages by installing them, and creates a **draft** GitHub Release with all assets, `SHA256SUMS`, `latest.json` (for the updater), and rendered winget/AUR manifests. A manual dry run does the same without creating the release.

**Architecture:** Gap analysis `docs/superpowers/plans/m6-gap-analysis.md` section 9 and "M6e". The build, bundle and package jobs already exist in `.github/workflows/brewery_ci.yml` (M6c/M6d) and are smoke-tested there. Make them reusable instead of duplicating them: `brewery_ci.yml` gains `on: workflow_call` with inputs `channel` (dev|stable, default dev) and `release` (bool), so the release workflow calls it; when `channel == stable` the jobs write `stable` into `crates/zed/RELEASE_CHANNEL` (and export `RELEASE_CHANNEL=stable`) before building, and use `CARGO_PROFILE_RELEASE_FAST_DEBUG=0`. The new `.github/workflows/brewery_release.yml` runs `version` (tag == `v` + `crates/zed/BREWERY_VERSION`, pre-release tags like `v0.1.0-rc.1` allowed only when the file says the same), calls the CI workflow, then `publish`.

**Tech Stack:** GitHub Actions (`workflow_call`, artifacts, `gh release create --draft`), Python (`script/brewery/render_manifests.py`, a new `script/brewery/release_assets.py`).

**Spec:** `docs/superpowers/specs/2026-10-10-brewery-design.md` (release, M6).

## Global Constraints

- Release assets (exact names): `Brewery-<ver>-x86_64-setup.exe`, `brewery-<ver>-linux-x86_64.tar.gz`, `brewery_<ver>_amd64.deb`, `brewery-<ver>-1.x86_64.rpm`, `brewery-<ver>-macos-aarch64.zip` (optional: the macOS job may fail without blocking the release), `SHA256SUMS`, `latest.json`, `winget/` manifests (zip or the three YAMLs), `aur/PKGBUILD` + `aur/.SRCINFO`, `jre-source.txt` (Adoptium source link for the bundled JRE, GPLv2 §3), optionally the daemon jar for reference. Verify the exact names the package jobs produce and keep them.
- `latest.json` (schema from `crates/auto_update/src/brewery_update.rs`): version, `notes_url` = `https://github.com/hteariH/brewery/releases/tag/v<ver>`, assets keyed `windows-x86_64` (setup.exe), `linux-x86_64` (tar.gz), `macos-aarch64` (zip, only if built), each with https `url` = `https://github.com/hteariH/brewery/releases/download/v<ver>/<file>` and `sha256`. Generated by `release_assets.py` (unit-tested), validated by parsing it with the same rules as `brewery_update.rs` (a test that loads the produced JSON through a small Rust test or a Python mirror of the rules — Python mirror acceptable, documented).
- winget and AUR manifests rendered by `render_manifests.py` with the real installer/tarball checksums (no placeholders on release runs).
- Stable channel: the built exe's VersionInfo must say ProductName `Brewery`; the Linux desktop file `io.github.htearih.Brewery.desktop`; macOS `Brewery.app`. Existing CI assert steps already switch on `RELEASE_CHANNEL` — make sure they read the stable value.
- Permissions: `contents: write` only on the `publish` job; everything else `contents: read`. `publish` runs only for tag pushes; `workflow_dispatch` (input `dry_run`, default true) uploads everything as workflow artifacts and prints the would-be release body.
- Draft only: the workflow never publishes the release, never pushes to winget/AUR (owner actions in M6f).
- Release notes body: from `CHANGELOG.md` section `## <ver>` if present, else a template with install instructions and the "unsigned" note; plus the SHA256SUMS block.
- Don't break normal CI: push/PR/dispatch behaviour of `brewery_ci.yml` stays as today when not called.
- actionlint clean.
